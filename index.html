Architecture as implemented

backs Sec. II-A to II-D

A shared four-layer convolutional encoder turns each 112×112 frame into a 256-channel 7×7 feature map. Each frame is refined by the attention module, the 16 frames are averaged and layer-normalised, and a capsule stage classifies the clip. Temporal information enters through per-frame modulation, not through a sequence model after pooling.

Attention module, applied per frame in this fixed order
StepStageMechanismApplied as
1Channel Average and max pooling share one bottleneck MLP at reduction ratio 8, summed, sigmoid. multiplicative
2Motion map Frame t concatenated with frame t-1, two parallel convolutions at 3×3 and 5×5, fused by 1×1 and sigmoid. map only
3Spatial A learnable 256-dimensional vector (the point prompt) is added to the input of this branch, which is combined with the motion map and reduced to a spatial map ending in a sigmoid. multiplicative
4Motion residual out + tanh(alpha) · (out · a_m), with alpha initialised at 0.1. The gate is signed, so motion regions can be amplified or suppressed. additive residual

The first frame has no predecessor, so it receives no motion map and skips steps 2 and 4. The fusion weight lam is used only to draw attention maps; it is not part of the forward pass.

The capsule stage forms 16 primary-capsule types of dimension 8 at each of the 7×7 positions (784 primary capsules) and runs three routing iterations to one 16-dimensional activity capsule per class. The class score is the capsule length. The transformation matrices are shaped (784, classes, 16, 8), so this layer grows linearly with the number of classes.

A seed fixes the data split and all random number generators. Capsule transformation weights are initialised from N(0, 0.01²); on UCF-101 the weights of the Sabour-style baseline are scaled by K/11 at initialisation (Section 27). The BaselineCNN rows of Table 1 use a separate softmax routine at learning rate 5e-4, a single seed and a split that is not stratified.

Reproducing the results

Requires a CUDA GPU, PyTorch with torchvision, and local copies of UCF-11 and UCF-101. The first pass over the data decodes video and is slow; later passes load from the on-disk frame caches.

  • Set DATASET_PATH (UCF-11) and UCF101_PATH (UCF-101) in Section 7. Each dataset root holds one folder per class.
  • For a fast check, set QUICK_TEST = True and run all cells. Every section then uses one seed and two epochs; the numbers are not meaningful.
  • Set QUICK_TEST = False and run all cells for the full run. Results, figures and split lists are written to results_final/.
  • The UCF-101 sections (24 to 27) come last and take the longest. Set RUN_UCF101 = False to stop before them.

UCF-101 is distributed by its original authors at crcv.ucf.edu/data/UCF101.php, and the UCF-11 YouTube Action set at crcv.ucf.edu/data/UCF_YouTube_Action.php.
